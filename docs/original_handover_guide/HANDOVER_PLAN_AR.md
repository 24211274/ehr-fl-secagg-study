# خطة تسليم الكود والتجارب للمشرف

هذه خطة تنظيم وتسليم، وليست مستودع GitHub منشأً أو حزمة تشغيل جديدة. لم تُعدّل الحملة المنفذة أو تُرفع ملفاتها إلى خدمة خارجية عند إعداد هذا الدليل.

## التسليم المقترح

ابدأ بمستودع GitHub خاص لعرض الكود، مع حزمة أدلة منفصلة للمشرف. احتفظ بالبيانات والأوزان والسجلات المفصلة خارج سجل Git إلى أن يكتمل تحديد ما يجوز مشاركته. المستودع الخاص يقلل نطاق الوصول، لكنه لا يمنح بحد ذاته حقوق إعادة التوزيع.

هيكل مقترح، وليس وصفاً لمستودع موجود:

```text
ehr-fl-secagg-study/
  README.md
  SUPERVISOR_CODE_GUIDE.md
  .gitignore
  .gitattributes
  executed/
    EHR_FL_Main_Experiments_Package_v1_0_3/
  analysis/
    Final_Score_Audit_Review_20260909T142009Z_2ad79bf6/
  results/
    summary_tables/
    figures/
  evidence/
    INDEX.md
    source_identity.json
  docs/
    REPRODUCIBILITY.md
    DATA_ACCESS.md
    CONTRIBUTIONS.md
```

توضع ملفات الشرح الجديدة خارج مجلد الكود المجمد. لا نعيد تسمية دواله أو نرتب داخله الملفات بعد التنفيذ ثم نزعم أن النسخة المعدلة هي الأصل. ملفات إعداد كل مهمة والحالات الابتدائية وقوائم السحب المتولدة داخل الحملة تحتاج فهرسة مستقلة؛ ملفات timing_B وtiming_C الموروثة ليست وحدها إعداد التجارب الرئيسية النهائي.

## ما يصل إلى الدكتور؟

رابط المستودع الخاص، ورابط الإصدار المحدد مع رقم commit، ودليل قراءة الكود، وفهرس أدلة التجارب. تربط كل نتيجة بإعدادها وبذرتها وبصمة النموذج ومعايرته. نرفق الجداول الكاملة لا أفضل البذور وحدها. نحفظ نسخة ZIP أصلية ذات SHA-256 معروف للمقارنة خارج Git.

الأدلة الكبيرة أو التفصيلية يمكن تسليمها عبر مساحة الجامعة المصرّح بها، مع بصمات الملفات. تُتاح الأوزان العالمية المختارة ومعايراتها بصورة منفصلة عند الحاجة؛ لا حاجة لرفع كل checkpoint وسيط أو التحديثات الفردية. تقارير الإكمال والتقييم لا تحتوي تلقائياً على الأوزان.

## الحدود قبل الرفع

لا ترفع مجلد المستخدم أو Downloads أو حملة WSL كاملة. استبعد بيئات Python، ملفات المفاتيح والرموز السرية، حالة بروتوكول الأقنعة، السجلات غير المراجعة، بيانات جلسات غير مصرح بمشاركتها، والكتب والمقالات والنماذج الجامعية غير اللازمة. استعرض قائمة الملفات أولاً، ثم افحص الملفات التي ستدخل Git فعلياً؛ .gitignore ليست مدقق أسرار ولا تزيل ما سبق تتبعه.

تظل حالة نشر وترخيص الـbenchmark غير مكتملة في السجل المتاح. لا نخترع DOI أو رابط Kaggle أو ترخيصاً عاماً. نحافظ على إشعارات تراخيص المصادر الخارجية، ونحسم ترخيص مساهمة المشروع بصورة مستقلة قبل أي نشر عام.

## الحفاظ على البايتات

يوصي هذا الدليل بمنع تحويل نهايات الأسطر في نسخ الأدلة والكود المجمد، مثلاً بإعداد ملائم في .gitattributes خارج المجلد المجمد، ثم إعادة فحص SHA-256 بعد commit وclone جديد. لا نغيّر قائمة البصمات الأصلية لتناسب تحويلاً أجراه Git. لا يكفي اسم tag وحده لإثبات التطابق؛ نسجل commit والبصمات ونحتفظ بالأرشيف الأصلي.

## خطوات GitHub

إنشاء مستودع خاص باسم مقترح ehr-fl-secagg-study، ثم تجهيز نسخة نظيفة منفصلة، ثم رفع الكود كملفات قابلة للتصفح وليس ZIP فقط. GitHub Desktop خيار مناسب على Windows؛ أبق خيار Keep this code private مفعلاً. لا تستخدمه لرفع مجلد الحملة الأصلية مباشرة.

بعد الرفع، أضف المشرف عبر Settings ثم Collaborators ثم Add people، ثم اختبر أنه يستطيع الوصول. في المستودع الخاص المملوك لحساب شخصي، collaborator يملك القراءة والكتابة؛ لا نصفه بأنه صلاحية قراءة فقط. يمكن استخدام مستودع منظمة بصلاحية مناسبة عندما تكون القراءة فقط شرطاً فعلياً.

أنشئ إصدار تسليم مثل thesis-submission-v1 بعد فحص الملفات. هذا إصدار تسليم أُنشئ بعد التجربة، وليس تاريخ تشغيل جديداً أو بديلاً عن رقم حزمة التنفيذ 1.0.3. أي تعديل لاحق يوثق بصورة منفصلة.

## إعادة الإنتاج ليست مجرد رفع الكود

قراءة الكود ممكنة دون بيانات أو تدريب. إعادة حساب المؤشرات من الدرجات المحفوظة لا تعيد تدريب النموذج. إعادة التجربة من الصفر تتطلب تجهيز البيانات والبيئة المعدلة والأصول المرتبطة بالمشغّل، واختبارها في مجلد جديد. لا نستبدل Flower المعدلة بآخر إصدار أو نستعمل أوامر إعادة التدريب فوق الحملة المكتملة.

هذا الدليل لا يؤكد أن نسخة الاستنساخ من GitHub جُرّبت من الصفر، ولا أنه أُجري فحص أسرار شامل للمشروع كله.

## مصادر تعليمات GitHub

راجعت تعليمات GitHub الرسمية لإنشاء المستودعات الخاصة، ورفع مشروع عبر GitHub Desktop، ودعوة المتعاونين وصلاحيات الحساب الشخصي، والإصدارات والملفات الكبيرة وتجاهل الملفات وملفات الاقتباس. عناوين المصادر مثبتة في SOURCES.md داخل هذه الحزمة.
